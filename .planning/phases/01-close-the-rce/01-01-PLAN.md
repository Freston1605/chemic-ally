<objective>
Close the engine half of the RCE with a shared, no-builtins validation boundary.

**User story (derived from the ROADMAP Phase 1 goal line):** **As a** user of the public equilibria calculator, **I want to** have every reaction string that is not exactly `formula = formula; K` rejected before chempy parsing, **so that** my legitimate chemistry still computes correctly and attacker code can never execute on the server.

This is the first of two plans. It extracts the working-tree RCE fix (already partially implemented in `equilibria.py` + `forms.py`) into the shared `calculations/security.py` module (SEC-05), rewires the engine layer to consume it, pins the `SAFE_EVAL_GLOBALS` call-site contract with a mock-based test (SEC-02), splits the engine error handler so failures return fixed constants instead of exception text (D-06), and adds direct predicate unit tests covering the SEC-01 acceptance matrix.

Purpose: The engine boundary is the last line of defense before chempy's eval-based parser (D-05) — it protects non-HTTP callers and must draw from the same acceptance rules as the form so the layers cannot drift (research Pitfall 6).

Output: `security.py` (shared module), rewired `equilibria.py`, SEC-02 pin test, engine error-copy assertions, Ka-mode engine solve test, and `test_security.py` predicate suite.
</objective>
